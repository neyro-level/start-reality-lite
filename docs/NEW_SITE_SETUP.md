# NEW_SITE_SETUP — трансформация копии Start Reality Lite

**Для AI-разработчика.** Этот документ применяют **в новом клиентском репозитории после копирования шаблона**. Исходный `start-reality-lite` не изменяется. Это рабочая инструкция, а не форма, бриф, план эпиков или задача на production.

## 1. Сразу после открытия папки

1. Прочитать корневой `AGENTS.md` и **все три** `docs/standards/AMS_{SITE,REALTY,UI}_CORE.md`.
2. Осмотреть `package.json`, `src/project/`, `src/app/`, `src/ui/`, `docs/seo/`, `fixtures/` и документацию дизайна.
3. Принять предоставленные владельцем материалы клиента как входные факты; не собирать дополнительный бриф и не создавать `PROJECT_PLAN.md`.
4. Определить реально доступные модули и подготовленные данные. Недостающий проверяемый факт не придумывать: использовать нейтральный текст, скрыть блок или оставить `noindex`.
5. Не переносить из демонстрационного шаблона фиктивные контакты и реквизиты в работающий клиентский проект.

## 3. Как менять структуру страниц без разрушения ядра

### Главная страница

Маршрут `/` уже существует. Основные изменения — в проектном copy и `HomePage` composition. Удалять, добавлять и менять порядок секций можно; сохранять Container/Section/shared primitives и server-first. Не переписывать Header/Footer на каждой странице.

### Статические разделы (услуги, о компании, контакты)

1. Проверить, есть ли `pageKey` в `src/project/grammar.config.ts`.
2. Обновить текст/наполнение в `src/project/**`, используя существующий `StarterPageShell` или новые секции `src/ui/sections/**`.
3. Если нужна новая страница, добавить **одну** запись в Grammar и соответствующую SEO Registry.
4. Добавить ссылку в `navigation.config.ts` только при существующем маршруте и готовом содержимом.
5. При неполном контенте сохранять доступность страницы, но закрыть индексацию через Content Gate/SEO-политику.

### Каталог, ЖК, застройщики, объекты, агенты

Сохранять имеющуюся цепочку `SnapshotRepository → DTO/ViewModel → UI`. Каталожные факты приходят из локального snapshot; названия URL собирает сайт. Новые карточки и секции используют DTO, **не читают фид, raw snapshot, файлы или Hub напрямую**. Цена отображается только с допустимой актуальностью `priceCheckedAt`; отсутствие факта — `null`/отсутствующий элемент, не придуманное значение.

### URL и SEO

Обычная структура сайта разрешается через `src/app/[...path]/page.tsx` и `src/app/site-page.tsx` с грамматикой из `src/project/grammar.config.ts`. **Не создавать отдельные файловые маршруты для каждого района или фильтра**, если действующий router уже покрывает их. Новые индексируемые фильтры — только из whitelist. Уже опубликованные URL сохранять либо сопровождать 308/410 по правилам SITE/REALTY Core.

## 4. Что защищено от обычной кастомизации

| Область | Правило |
|---|---|
| `src/platform/**` | Не менять при смене бренда, страниц или контента; изменение только отдельным архитектурным решением владельца |
| `src/platform/hub/contract.ts` и snapshot/verifier/store/worker | Не менять контракт подписанного snapshot и правила доверия ради конкретного клиента |
| Repository/DTO и публичная identity | Не ломать UID, `publicUrlId`, lifecycle, slug history, privacy и price freshness |
| `src/platform/leads/**` | Не обходить encrypted durable spool; не создавать новую систему заявок |
| `src/ui/primitives/**` | Не делать второй набор Button/Input/Dialog; только обоснованные variants по AMS UI CORE |
| `src/app/api/**`, `src/proxy.ts` | Не переписывать при обычной замене страниц/текстов; это безопасность и инфраструктура |
| `docs/standards/**` | Три конституции неизменяемы в рамках клиентской настройки |

Изменение защищённого слоя возможно **не потому, что так проще для страницы**, а только при явной новой функции/архитектурном требовании и разрешении владельца.

## 5. Дизайн-система

Базовый нейтральный визуальный канон шаблона — `docs/TEMPLATE_DESIGN_SYSTEM.md`. Для клиента создать **одну** действующую `docs/PROJECT_DESIGN_SYSTEM.md` из `docs/template/PROJECT_DESIGN_SYSTEM.md`, если требуется зафиксировать отличия бренда. Шаблонная дизайн-система — отправная точка, а не конкурирующий проектный канон.

По умолчанию: синяя палитра, Manrope, компактные радиусы около 5 px, shadcn/ui (Radix), Lucide, Tailwind CSS 4. Не переименовывать весь префикс `--sr-*` ради нейтральности: это техническая деталь, не бренд пользователя. Значения токенов и темы меняются в `src/project/theme.css` при необходимости.

## 6. Что не считается готовым к публикации

Не включать `INDEXING_MODE=public` и не считать сайт запущенным, пока присутствуют demo-данные, не утверждены юридические тексты и нет настоящего транспорта заявок. Разработка в `DATA_MODE=local` допустима до готовности AMS Data Hub. Реальное подключение к Hub, production Docker и secrets — отдельная задача; **не создавать и не имитировать их автоматически**.

## 7. Завершение конкретной задачи

По итогам работы сообщать коротко:

- что изменено и какие существующие компоненты использованы;
- какие новые маршруты/SEO-правила появились;
- трогались ли защищённые контракты (нормально — нет);
- какие проверки реально выполнены, а какие не запускались;
- что ещё зависит от данных владельца или будущей интеграции.

Работать небольшими коммитами в новом клиентском репозитории и соблюдать его PR/merge-политику. **Без самостоятельного брифинга, создания мастер-планов и массовой перестройки ядра.**
